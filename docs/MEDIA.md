# Музыка, изображения и файлы

Модули подключаются независимо. `media` включает все три; приложение без них не получает CPAL, Symphonia или декодеры изображений.

```toml
rusterize = { path = "../../crates/rusterize", features = ["media"] }
# Или features = ["audio", "image-codecs", "files"]
```

Рабочий пример — [examples/media](../examples/media/src/lib.rs). Он открывает MP3/WAV и PNG/JPEG, показывает спектр и волну, позволяет перематывать музыку, одновременно запускать короткий эффект, менять громкость, экспортировать настройки и восстанавливать их при следующем запуске. В общем коде примера нет `std::fs`, потоков ОС, Windows API или `Instant`.

```sh
python scripts/build.py --platform windows --package rusterize-media
python scripts/build.py --platform web --package rusterize-media
python -m http.server 8000 --bind 127.0.0.1 --directory dist/web/rusterize-media
python scripts/build.py --platform android --package rusterize-media --abi arm64-v8a --abi x86_64
python scripts/build.py --platform linux --package rusterize-media
python scripts/build.py --platform macos --package rusterize-media
```

Сначала запускаются встроенные демонстрационные материалы; звук включается кнопкой. `--no-default-features` у **пакета примера** исключает встроенные MP3/PNG, сохраняя загрузку файлов и все медиавозможности. Синтезированный короткий WAV-эффект остаётся. Итоги проверок и размеры: [MEDIA_VALIDATION.md](MEDIA_VALIDATION.md).

## Запросы и результаты

Используется существующий `RequestId` → `Event::NativeResult { id, result }`. Сохраняйте ID и сопоставляйте ответ с ожидаемой операцией:

```rust,ignore
let pick = context.select_file(rusterize::native::FileDialog::default());
// NativeResponse::Files(locations) →
let read = context.read_file(locations[0].clone());
// NativeResponse::Bytes(bytes) →
let decode = context.decode_audio(bytes);
// NativeResponse::Audio(clip) →
let mut music = rusterize::audio::Player::new(clip)?;
music.set_volume(0.6)?;
music.play()?; // В браузере — из обработчика доверенного нажатия.
```

Загрузка и декодирование не выполняются в `draw`. На нативных платформах у Engine один лениво создаваемый worker с очередью до 16 незавершённых запросов: чтение, запись и декодирование исполняются по порядку. Завершения доставляются в существующем цикле событий на потоке приложения; pending-работа поддерживает пробуждение даже без пользовательской анимации. При Suspend результаты ждут Resume. Переполнение возвращает ошибку, а не блокирует UI.

В браузере File/IndexedDB/Web Audio работают асинхронно, PNG/JPEG декодируются тем же Rust-кодом в отдельном Web Worker. WASM threads, SharedArrayBuffer и COOP/COEP не нужны. Браузерные запросы могут завершаться не по порядку: следующую зависимую операцию надёжнее запускать после результата предыдущей. Worker загружает вторую копию `app.wasm`, но не создаёт второй Application. CSP должен разрешать свой worker и WASM.

При уничтожении Engine ожидающие операции отменяются, запоздалые ответы не вызывают приложение. Уже начатая нативная операция может закончиться, включая атомарное сохранение. Это не API принудительной отмены системного I/O. Произвольные пользовательские задачи/ZIP-разбор не переносятся автоматически в worker: разбивайте их на шаги или добавляйте собственный адаптер.

## Аудио

`Clip` содержит декодированный interleaved PCM и 512 пиков волновой формы. `clone()` разделяет ресурс. `Player` — один голос; музыка и эффекты используют отдельные плееры с общим Clip, без повторного декодирования. Подготовьте пул эффектов заранее: `Player::new` открывает устройство синхронно и может занять заметное время, особенно на Android. Не создавайте плеер на каждую ноту.

Методы: `play`, `pause`, `stop`, `seek(seconds)`, `set_volume(0.0..=1.0)`, `snapshot`, `poll_event`. Stop сбрасывает позицию; Play после Ended начинает сначала. Seek допустим от нуля до длительности включительно; NaN, отрицательные значения и выход за пределы возвращают Error. `snapshot` даёт `PlaybackState`, позицию, длительность и оценку `output_latency` в секундах. Состояния: Stopped, Playing, Paused, Ended, Interrupted, Failed.

Вызывайте `poll_event` из Frame, пока плеер активен (`context.set_animation(true)`). Ended/Interrupted/Error выдаются один раз за переход состояния. Устройство может отказать уже после успешного Play; ошибка снимка/событие требуют остановки игрового времени и пересоздания плеера. Drop освобождает поток или Web Audio nodes; Drop последнего Clip освобождает PCM. Пауза сохраняет нативный поток и выдаёт тишину, чтобы повторный Play не открывал устройство заново.

| Платформа | Декодирование и вывод | Что означает позиция и задержка |
| --- | --- | --- |
| Windows | Symphonia → CPAL/WASAPI | Оценка позиции на выходе по timestamp playback/callback. Учитывает очередь уже записанных буферов. |
| Linux | Symphonia → CPAL/ALSA | Тот же алгоритм; качество timestamp зависит от ALSA-устройства и звукового сервера. Нужны development-пакет `libasound2-dev` при сборке и системная ALSA при запуске. |
| macOS | Symphonia → CPAL/CoreAudio | Тот же алгоритм с timestamp CoreAudio. Сборщик связывает системные аудиофреймворки. |
| Android 8+, API 26 | Symphonia → CPAL/AAudio + аппаратные timestamp через ndk | Сегменты привязаны к номерам выходных frames; позиция читается из AAudio timestamp CLOCK_MONOTONIC и интерполируется в том же clock domain, с пределом frames_written. До готовности timestamp используется frames_read. JNI устанавливает application context, AudioManager управляет audio focus. |
| Браузер | `decodeAudioData` → AudioBufferSourceNode/GainNode | Позиция **рендера** по AudioContext.currentTime, а не акустическая позиция. `output_latency` отдельно суммирует доступные baseLatency/outputLatency; ноль может означать отсутствие оценки. |

Нативный колбэк лишь читает PCM, линейно пересэмплирует и применяет громкость. В нём нет файлового I/O, декодеров, FFT, выделений памяти и mutex. Поддерживаются mono/stereo источники; stereo сводится в mono при mono-выходе, дополнительные выходные каналы заполняются тишиной. На каждый голос открывается поток; микширование между голосами выполняет ОС. Это компактный вариант для музыки и небольшого пула эффектов, без sample-accurate планировщика и общего многоголосного микшера.

На нативных платформах хранится кольцо из 64 временных сегментов вывода. Между timestamp позиция интерполируется, но не выходит за конец уже отправленного PCM. Пауза/перемотка меняют слышимую позицию после ранее поставленных в очередь буферов, а не мгновенно в момент клика. Интервал реакции — следующий колбэк плюс очередь устройства. Числовое разрешение PCM — один sample (например, 1/48000 с); это **не гарантия** точности звука до такого интервала. Clock ОС, планировщик, драйвер, преобразование частоты, устройство и Bluetooth добавляют погрешность. Если драйвер не даёт положительной разницы timestamp, оценка очереди равна нулю. Реальная акустическая задержка не измерена.

В CPAL 0.16 AAudio callback и playback timestamp имеют разные начала отсчёта. Поэтому Android-подключение не вычитает их: оно сопоставляет сегменты с аппаратным frame_position, использует CLOCK_MONOTONIC и ограничивает прогноз числом записанных frames. При недоступном аппаратном timestamp используется frames_read — это менее точная начальная оценка.

В Web Audio позиция и пауза используют аудиочасы, а не RAF или Date.now. Шаг обновления часов зависит от квантов движка (часто 128 samples) и настроек приватности; UI обновляется с частотой кадров. Смена источника при seek/stop выполняется через Web Audio, ранее переданный устройству звук может доиграть. Для ритм-игры храните пользовательскую калибровку ввода/вывода, учитывайте различие render/output clock и снимайте позицию при обработке ввода. Не суммируйте `Event::Frame.delta` для игрового аудиовремени. Sample-accurate синхронизация нескольких Player, time-stretch и гарантированная задержка в миллисекундах не предоставляются.

`Clip::read_pcm(start_frame, output)` копирует до 32768 interleaved samples без декодирования; за концом — нули. `waveform()` возвращает закэшированные пики. `spectrum(position)` вычисляет 32 логарифмические полосы Goertzel по окну Hann 1024 frames на стороне UI, вне аудиоколбэка. Это визуализация, а не измерительный спектроанализатор; частоту обновления выбирает приложение.

Источники ограничены 32 МиБ, PCM — 256 МиБ, mono/stereo, 8–192 кГц. Нативный WAV поддерживает PCM/float, MP3 — через Symphonia; ADPCM, FLAC, Ogg, стриминг и URL-загрузка не входят в контракт. В браузере доступность MP3/WAV зависит от медиадекодера движка; он пересэмплирует в частоту AudioContext, поэтому длина может отличаться на несколько samples. Браузер выделяет внутренний AudioBuffer до проверки PCM-лимита; эта проверка не ограничивает его пиковое потребление памяти. Одновременно удерживаются до 16 браузерных clips и 32 players. На нативной стороне общий бюджет удерживаемых Clips задаёт приложение.

При первой попытке Play браузер требует доверенный click/key; запрос может вернуть ошибку разблокировки, после чего его можно повторить по нажатию. Асинхронное завершение загрузки само по себе не заменяет жест. Suspend/скрытие страницы, audio-focus loss Android и suspend/interrupted AudioContext прерывают воспроизведение. Resume не запускает звук сам. Нативный desktop Suspend связан с минимизацией/скрытием окна, а не просто переключением фокуса; фоновые воспроизведение Android/медиауведомления не реализованы. После смены/отключения устройства пересоздайте Player. При восстановлении приложения после уничтожения процесса восстановите сохранённое состояние отдельно.

## Изображения

`Image::rgba` остаётся прежним. `Image::decode(&bytes)` синхронно декодирует PNG/JPEG из памяти; для UI используйте `context.decode_image(bytes)` и `NativeResponse::Image`. Получается обычный immutable Image: повторный рисунок и clone используют те же пиксели/ID и существующий кэш оболочки.

Пределы: 32 МиБ исходника, 16384 по каждой стороне, 16 777 216 пикселей, ограничение выделений декодера 128 МиБ. Размеры проверяются до полной распаковки. Повреждённые данные возвращают Error. Результат — 8-bit RGBA со straight alpha; прозрачность PNG сохраняется, JPEG получает alpha 255. EXIF orientation применяется до передачи Image, включая смену ширины/высоты при повороте. Анимация, HDR и управление ICC-профилями не поддержаны; декодируется одно изображение. Ограничения уменьшают риск чрезмерных ресурсов, но не гарантируют отсутствие OOM при нескольких больших изображениях и копиях между WASM/JS/Canvas.

## Файлы и постоянные данные

`Context::select_file` развивает существующий FileDialog и возвращает `NativeResponse::Files(Vec<FileLocation>)`. Отмена — `Cancelled`; отказ доступа и ошибка — `Err(Error)` с причиной. `read_file` → Bytes, `write_file` → Done, `release_file` освобождает временный браузерный токен или право нового Android-экспорта. Не считайте завершение fallback download подтверждением записи на пользовательский диск.

`FileLocation` различает `SystemPath(PathBuf)`, `ContentUri(String)` и `BrowserToken(String)`. Не передавайте URI/токен в `std::fs` и не сохраняйте временный токен для следующего запуска. Android использует ACTION_OPEN_DOCUMENT/CREATE_DOCUMENT/TREE и ContentResolver, без разрешения полного доступа к внешнему накопителю. Сохранение долгосрочного URI-разрешения не предоставляется; импортируйте данные в хранилище приложения. Выбор дерева доступен, но общий API перечисления дерева пока не добавлен; существующий `web::read_directory` сохраняется.

`context.store_data("dev.example.app", "settings", bytes)` сохраняет один ключ; `load_data` возвращает Bytes или Missing. Пустое значение отлично от отсутствующего. App/key — 1–120 ASCII букв, цифр, точек, `_`, `-`; переходы по каталогам и системные имена Windows отклоняются на всех платформах. Для пользовательских названий храните собственный индекс; ID приложения должен быть стабильным между версиями.

| Платформа | Расположение |
| --- | --- |
| Windows | `%LOCALAPPDATA%/<app>/<key>` |
| Linux | `$XDG_DATA_HOME/<app>/<key>`, либо `$HOME/.local/share/<app>/<key>`; нужен абсолютный путь |
| macOS | `$HOME/Library/Application Support/<app>/<key>` |
| Android | `Context.getFilesDir()/<app>/<key>` |
| Браузер | IndexedDB `rusterize-data-v1`, object store `data`, ключ `[app, key]`, в пределах origin |

Чтение/запись — до 32 МиБ на операцию, без streaming/chunked API. Не храните все песни в одном огромном ключе. Браузерное хранилище переживает reload/перезапуск, но зависит от квоты, приватного режима, удаления данных сайта и eviction браузером; это не резервная копия. Смена origin создаёт отдельное хранилище. Ошибка квоты/транзакции возвращается приложению.

Системные пути заменяются через уникальный соседний временный файл, write + sync_all + rename (Windows: MoveFileExW с REPLACE_EXISTING/WRITE_THROUGH). При ошибке до успешной замены прежний файл остаётся. Гарантии зависят от файловой системы; fsync родительского каталога на Unix не выполняется, поэтому полная сохранность при отключении питания не обещается. IndexedDB commit атомарен; File System Access использует createWritable/close с abort при ошибке. Android-провайдеры не дают общей гарантии атомарной замены: поддерживается запись **нового** документа после CREATE_DOCUMENT, повторная запись в существующий ContentUri возвращает явную ошибку до открытия на запись. Настройки Android используют атомарное app-private хранилище.

## Системные возможности и совместимость

Сохраняются `Context::set_window_state`, старый `file_dialog`, clipboard и браузерные файловые методы. Новые NativeCapabilities: AUDIO, IMAGE_CODECS, FILE_IO, STORAGE. Биты учитывают Cargo features; они означают наличие реализации, а не доступность устройства, разрешение пользователя или свободное место. Всегда проверяйте результат операции.

Android теперь объявляет и реализует FILE_DIALOG и WINDOW_STATE; Normal/Fullscreen меняют системные панели, Minimized/Maximized возвращают понятную ошибку. В браузере также доступен только Normal/Fullscreen и действуют требования жеста/разрешений. Desktop использует существующее управление окном; macOS явно отклоняет неизвестные значения. Clipboard требует системного доступа; браузер — secure context и разрешение, фоновые чтения Android ограничены ОС. Неподдерживаемые операции не должны маскироваться под Done. Возможности произвольного размера/позиции desktop-окон не переносятся на мобильную ОС и браузер.

`time::monotonic_seconds()` — переносимые часы дедлайнов/ввода, независимые от Frame; начало отсчёта произвольно и значение нельзя сохранять между запусками. `time::unix_seconds()` — wall clock для истории, может измениться после синхронизации системного времени. В вебе это performance.now/Date.now через существующий host bridge, без `std::time::Instant/SystemTime` в приложении. Ни одни из них не заменяют Player::snapshot для музыки.

Новые варианты `Event::AudioInterrupted` и `NativeResponse` требуют обновить исчерпывающие match либо добавить fallback. `NativeResponse::Bytes` теперь доступен также на native. Старые запросы и RZ03 display-list ABI сохранены. Новые opcodes: 40–44 файлы/данные, 48–49 часы, 50–51 декодеры; Android 60–63 picker/focus; Web Audio 70–80. При обновлении библиотеки скопируйте соответствующие `hosts` и сборщик, особенно Java nativeCreate(Context), media.js и media-worker.js. Генератор уже включает их.

## Зависимости

CPAL 0.16.0 — Apache-2.0, Symphonia 0.5.5 — MPL-2.0, image 0.25.6 — MIT OR Apache-2.0, Android ndk-context 0.1.1 и ndk 0.9.0 — MIT OR Apache-2.0. У Symphonia включены только MP3/WAV/PCM, у image — PNG/JPEG. CPAL/Symphonia не собираются в WASM; браузер использует системный Web Audio. Отдельного C-медиадвижка, FFmpeg runtime или wasm-bindgen glue не добавлено. FFmpeg используется только необязательным скриптом создания собственных тестовых материалов.

При распространении включайте лицензии зависимостей, а для MPL-компонентов — предусмотренные лицензией сведения и доступ к их исходникам/изменениям. [Источники лицензий и версии](MEDIA_LICENSES.md). Встроенные музыка и рисунок созданы скриптом проекта, сторонних медиаматериалов нет.
