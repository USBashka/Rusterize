# Переход LyriXX на общие медиасервисы

LyriXX изучен как источник требований; его исходники и сборки этой работой не изменены. Рабочая реализация и переносимый пример находятся в Rusterize. Успех проверки библиотеки LyriXX для Android сам по себе не подтверждает работу звука, файлов или APK.

## Зависимости и оболочки

В Cargo.toml приложения включить у Rusterize `features = ["media"]`, обновить скопированные hosts и `scripts/build.py` из этой ревизии. Сохранить `native` и прочие реально используемые features. Удалять Windows Media Foundation/WIC зависимости только после замены использующих их модулей; Windows-расширения окон можно оставить под `cfg(windows)`.

`uuid = 1.27.0, features = ["v4"]` — отдельная причина нынешней ошибки wasm32: генератор случайных чисел не настроен. Это не ошибка аудио или Rusterize. В `src/package.rs` UUID используется для временного имени, в `src/editor.rs` — для ID новой карты; `Uuid::parse_str` нужен валидатору. Перенос атомарной записи в `store_data` убирает UUID только из первого места.

Для редактора выбрать совместимую с LXX стратегию UUID: например, UUID v5 с отдельным namespace приложения и уникальной последовательностью редактора, если профиль LXX допускает эту версию; либо небольшой платформенный адаптер безопасных случайных байтов (на вебе `crypto.getRandomValues`) и `Uuid::Builder::from_random_bytes`. Не заменять UUID произвольной строкой или хэшем, если валидатор требует UUID. Стратегия уникальности/копирования карты остаётся решением LyriXX.

Простое включение feature `uuid/js` устраняет compile_error, но добавляет wasm-bindgen/js-sys imports. Текущий загрузчик Rusterize использует собственные импорты `rusterize` и не создаёт wasm-bindgen glue. Поэтому такой вариант потребует также `wasm-bindgen` post-processing и изменения веб-загрузчика; один успешный `cargo check` недостаточен. Не включать uuid/js во все нативные сборки ради обхода проверки.

## `src/audio.rs`

Сохранить прикладной фасад Audio и его команды intro/menu/song, mute, группы громкости, hover/confirm/wrong-letter/missed-line. Его внутренний Windows worker, Media Foundation и собственный расчёт позиции заменить на:

- `Context::decode_audio(Vec<u8>)` → `NativeResponse::Audio(Clip)`; закэшировать подготовленные Clips.
- Один Player для текущей музыки и заранее созданный небольшой пул Player для перекрывающихся коротких эффектов. Один эффектный Player при повторном запуске обрывает предыдущий экземпляр; размер пула определяет приложение.
- `play`, `pause`, `stop`, `seek`, `set_volume`; preview-start передавать в seek после загрузки. Диапазон предпрослушивания и запрет повторения остаются логикой LyriXX.
- `snapshot().position` для игрового времени; `poll_event()` для завершения, прерывания и ошибки. Не продвигать счёт/строки, пока загрузка не завершилась или звук прерван.
- `Clip::read_pcm` для существующего анализа или `spectrum`/`waveform` для готовой визуализации. Не декодировать повторно на каждом кадре.

Начальный экран браузера должен ждать нажатия для Play. На Suspend/audio-focus loss приостановить игровой сеанс; после Resume предложить явное продолжение. При потере устройства пересоздать плеер из сохранённого Clip. Пользовательскую калибровку задержки хранить отдельно: native snapshot оценивает выходную позицию, web snapshot — render clock. Результаты реального акустического измерения на целевых устройствах ещё нужны для ритм-игры.

## `src/song_images.rs` и `src/package.rs::image`

WIC-декодирование заменить запросами `decode_image`, кэшировать возвращённый Image по ID ресурса/хэшу архива. Не запускать синхронный `Image::decode` из draw и не делать повторные запросы при каждом перерисовывании. Для маленьких заранее подготовленных RGBA оставить `Image::rgba`. Прозрачность и EXIF orientation уже обрабатывает фреймворк.

## Библиотека, редактор, настройки и история

`src/package.rs` уже имеет `Package::unpack(&[u8])` и `archive() -> Vec<u8>`: использовать эти входы вместо `Package::read(Path)`. Путь в библиотеке заменить прикладным ID и `FileLocation` только на время импорта/экспорта. Поток импорта: `select_file` → `read_file` → unpack/валидация → сохранение архива и обновлённого индекса. Поток экспорта: `archive` → save picker → `write_file` → сообщение об успехе только после Done. Освобождать токен через `release_file`, обрабатывать Cancelled без ошибки пользователя.

Не размещать новые данные рядом с EXE: `src/lib.rs` (настройки), `src/selection.rs` (состояние/история), `src/package.rs::storage/atomic_write` перевести на `load_data/store_data` с постоянным app ID, например `dev.lyrixx.app`. Текстовые TOML/JSON/историю кодирует приложение; framework хранит байты. Отсутствующий ключ Missing, пустой файл, повреждение формата и отказ доступа различать. Для первого desktop-запуска предусмотреть однократный импорт прежней папки рядом с EXE с явным выбором пользователя, без удаления оригинала.

Вместо обхода системной папки хранить собственный индекс карт. Изменения двух ключей не являются общей транзакцией: сначала сохранить новый архив, затем индекс; при старте уметь восстановить индекс/убрать сиротские записи по собственной схеме. У Rusterize пока нет общего delete/list API хранилища: для полноценного удаления большой библиотеки понадобится такое расширение или схема повторного использования ключей. Не называть пустую запись физическим удалением.

В LyriXX лимиты архива достигают 128 МиБ на ресурс и 256 МиБ суммарно. Новый переносимый read/write ограничен **32 МиБ на операцию**. Для карт большего размера нужен следующий этап — потоковый/chunked контракт и проверка ZIP без загрузки всего архива. До него интерфейс должен заранее показывать понятный отказ, а не обещать импорт любых ранее допустимых карт. Тяжёлый разбор ZIP/TOML разделить на шаги или собственную worker-задачу; новый framework worker автоматически обслуживает только предоставленные файловые/медиазапросы.

`src/lib.rs` использует Instant для переходов/паузы: заменить прикладные дедлайны на `time::monotonic_seconds` или существующие Frame.elapsed/delta, в зависимости от того, должна ли анимация останавливаться в фоне. `src/selection.rs::unix_now` перевести на `time::unix_seconds` для сохраняемой истории. Эти часы не заменяют audio snapshot.

## Что остаётся в LyriXX и как принять миграцию

LXX/LXT, Unicode/BCP47, TOML/ZIP-валидация, SHA-хэши, тайминг строк, моды, scoring, SS–F, история, редактор и правила preview остаются в приложении. Сам факт компиляции этих модулей не проверяет взаимодействие с ОС.

Проверить отдельно: Windows EXE; Linux GTK/ALSA; macOS AppKit/CoreAudio; настоящий Android ARM64 APK; WASM в нескольких движках. Для каждого — импорт реальной LXX, декодирование обложки, preview с нужной позиции, seek/pause, музыка одновременно с эффектами, возвращение из фона, сохранение/перезапуск, отмена picker, заполненная квота/нет доступа, экспорт с проверкой байтов. Для ритм-игры измерить аудиовизуальную задержку и точность на динамиках, проводном и Bluetooth-выходе. Проверка Rusterize media демонстрирует инфраструктуру, но не заменяет этот приёмочный прогон LyriXX.
