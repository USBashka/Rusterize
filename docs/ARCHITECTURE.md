# Архитектура

Опциональный [WebView](WEBVIEW.md) использует очередь нативных сервисов, а не display list. WebView2, WKWebView, Android WebView и WebKitGTK владеют дочерним представлением и собственным браузерным процессом. Нативные callbacks ставят события в очередь и будят UI-поток; приложение получает их после освобождения заимствований. `Destroy` отменяет доставку старых событий, в том числе после повторного использования ID. Feature выключена по умолчанию.

Опциональный модуль [WGSL](SHADERS.md) переводит шейдеры Naga при сборке. Все платформы записывают команды Shader и исполняют их при композиции. Windows использует совместные текстуры OpenGL/D3D11 и Direct2D, при отсутствии interop — Image с readback; веб передаёт WebGL canvas в Canvas 2D через drawImage. Android связывает выходную текстуру с HardwareBuffer/EGLImage и передаёт неизменяемый hardware Bitmap системному Canvas; API 26–28, программный Canvas и недоступный interop используют readback. Linux и macOS смешивают шейдерные GPU-текстуры с загружаемыми слоями Cairo/CoreGraphics в GtkGLArea и NSOpenGLView. Системное рисование текста, фигур и масок clip сохранено. Явный ShaderRenderer::render по-прежнему возвращает CPU Image. Naga отсутствует в runtime-зависимостях. Без feature `shaders` модуль не собирается.

```text
Application (Rust)
  event + Context → состояние → draw + Canvas
                                 ↓
                           проверенный Scene
                          /                \
                Direct2D (Rust)       RZ03 resources + display list
                      ↓                ↓      ↓       ↓
                    Win32          Android   GTK4   AppKit
                                    Canvas   Cairo  Core Graphics
```

Ядро отделено от окон и SDK. `Canvas` записывает типизированные команды; небольшие фигуры хранятся непосредственно в enum. `Path` и `Image` разделяют неизменяемые данные через Arc. Выделение памяти display list и бинарного буфера повторно используется. Это позволяет тестировать приложение без окна и создавать другие адаптеры.

Windows исполняет типизированный Scene напрямую. Остальные оболочки получают один буфер RZ03 на кадр и не делают JNI/FFI-вызов для каждой фигуры. В начале пакета идут загрузки и освобождения ресурсов, затем команды со ссылками по ID. Stateful Encoder загружает пиксели только при первом появлении Image; повторные кадры не сериализуют их заново. Исчезнувший из сцены ресурс освобождается, при возвращении загружается повторно. Android использует безопасную копию `byte[]`, Swift — `Data`, Linux читает Rust-буфер синхронно. При потере кэша или пропуске пакета оболочка очищает ресурсы и вызывает rusterize_reset_resources перед новым кадром. RZ02 несовместим с новым форматом: обновляй библиотеку и host одновременно.

Системные объекты живут только в UI-потоке. Host выдаёт непрозрачные числовые handles, а не Rust-указатели; удалённый или чужой handle получает FAILED. Регистрация сервиса и нативный callback принимают указатели доверенной оболочки; эти ABI помечены unsafe на стороне Rust. Возвращённые буферы действительны до следующего изменяющего вызова для того же handle. Rust callbacks не должны паниковать; в release применяется panic=abort.

Win32 балансирует BeginPaint/EndPaint и BeginDraw/EndDraw, обрабатывает resize и DPI. При потере Direct2D target ресурсы освобождаются и пересоздаются. Ресурсы DirectWrite ограничены кэшем; изображения освобождаются после кадра, в котором перестали использоваться. Android освобождает ссылки на Bitmap без преждевременного recycle, потому что GPU display list ещё может использовать ресурс.

GTK и AppKit — небольшие системные оболочки, а не альтернативные реализации логики. Они используют Pango/TextKit для текста, системные циклы событий и ограниченные по частоте запросы анимации. Дополнительные платформы подключаются через тот же ABI либо через Rust `Renderer`; iOS, BSD и embedded пока не реализованы.

Веб-оболочка `hosts/web/rusterize.js` загружает `wasm32-unknown-unknown` cdylib с тем же `export_app!` ABI. RZ03 исполняется в Canvas 2D, события DOM передаются в общий Engine. BigInt сохраняет 64-битные handles и ID ресурсов. Синхронные импорты `rusterize.service` / `service_read` обслуживают текст, явный WebGL readback и извлечение событий; `request` / `cancel_requests` — асинхронные системные операции. Обычный Shader replay не возвращает пиксели в WASM. JavaScript не входит повторно в Rust из сервиса или Promise: завершение будит RAF и очередной poll. После выделения памяти ответа создаётся новый view WASM memory. WebView представлен изолированным iframe, файлы — токенами с временем жизни экземпляра. [Подробности и ограничения](WEB.md).

Общий слой использует нативные текстовые движки: DirectWrite, Pango, Android StaticLayout и AppKit TextKit поверх системной типографики. `TextLayout` хранит запрос и проверенные метрики; измерение и отрисовка используют одну реализацию настройки layout в каждой оболочке. Rust не оценивает ширину по числу символов и не реализует собственный shaping.

`Context` хранит очередь системных запросов. Оболочка извлекает запрос, освобождает заимствование приложения, выполняет нативную операцию и доставляет `Event::NativeResult`. Это допускает вложенный цикл событий модального диалога. Повторный poll не исполняет очередь рекурсивно; пакет ограничен 64 запросами. Неудача операции не уничтожает приложение. Коды запросов и ответов описаны в протоколе; `NativeCapabilities` сообщает фактический набор адаптера.

`Application::native_draw` вызывается после общих команд внутри нативного кадра. Приложение получает исходные объекты SDK: COM-интерфейсы Direct2D/DirectWrite, Java Canvas/View/JNIEnv, Cairo/GTK или Core Graphics/AppKit. Объекты заимствованы на время callback; приложение не уничтожает target/window, не вызывает BeginDraw/EndDraw и балансирует собственные состояния. Нативные операции не сериализуются и остаются платформенным кодом. DirectWrite layout доступен отдельно как настоящий `IDWriteTextLayout`, включая hit testing и форматирование диапазонов.

Пока нет готовых переносимых модулей дерева виджетов, IME/composition, accessibility tree, меню, многоконности и системных уведомлений. Доступ к объектам SDK позволяет написать платформенное расширение, но не заменяет реализацию этих модулей. Подробная матрица — в [NATIVE_API.md](NATIVE_API.md).
