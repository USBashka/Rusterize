# Проверки версии 0.1

## WGSL: локальная проверка 8 октября 2026

- Компилятор WGSL — отдельная build-dependency на Naga 24 (совместимая с MSRV 1.85), runtime добавляет только `glow` и системные GL API. `cargo tree -e normal` подтверждает отсутствие Naga и wgpu в приложении. Стандартные default-members исключают сборочный пакет и шейдерный пример.
- Windows: полный workspace, ядро без default features, Clippy с `-D warnings`, rustfmt и документация проверены. Пять отдельных GPU-тестов выполняются на **NVIDIA GeForce RTX 4070 Ti SUPER, OpenGL 3.3, драйвер 616.92**: UV, uniform layout, альфа, входная текстура, кэш, анимация, некорректные запросы, повторное создание контекстов, пауза/возобновление, DPI и композиция Direct2D. Пример исполняется в настоящем Win32-окне с изменением размеров и автоматическим завершением.
- Android: подписанный debug APK собран для ARM64 и x86-64. В **Android 16.1 x86-64 emulator** запущен вариант `--features self-check` с проверкой реальных выходных пикселей. Скрипт `scripts/check_android_shaders.py` подтвердил изменение пикселей при анимации, отсутствие изменений на паузе, resize, DPI и восстановление после фона. Физическое Android-устройство здесь не проверялось. При изменении конфигурации Android может пересоздать Activity; сохранение состояния между уничтоженными Activity остаётся задачей приложения.
- `shaders.exe` — **408 576 байт**, обычная `gallery.exe` — **318 976 байт**, ровно как до добавления шейдеров. Это разные демонстрационные приложения, разница между ними не является точным измерением накладных расходов одной feature. APK с двумя ABI и самопроверкой — **557 614 байт**.
- Windows EXE запущен отдельно от файлов проекта; проверены импорты системных DLL, включая `opengl32.dll`, без VCRUNTIME/MSVCP или поставляемых DLL компилятора. Нужен установленный драйвер с OpenGL 3.3; это не обещание работы на базовом программном OpenGL 1.1 в чистой Windows/виртуальной машине.
- Release-бенчмарк на указанной NVIDIA, по 100 кадров после прогрева: 256×128 — **0,306 мс**, 512×256 — **0,507 мс**, 1024×512 — **1,132 мс**. Включены исполнение шейдера, синхронный GPU readback, разворот строк и создание Image; не включены нативная композиция, display-list транспорт и показ окна. Значения не являются обещанием для другого устройства.
- Linux/macOS проверяются заданиями текущего [CI](https://github.com/USBashka/Rusterize/actions/workflows/ci.yml): сборка нативного примера, запуск GPU-тестов и создание реального offscreen-кадра. Windows CI собирает пример, но GPU-тесты выполнялись локально: стандартный Windows runner не гарантирует OpenGL 3.3. Отдельное задание проверяет MSRV ядра и WGSL-компилятора.

Текущий путь — OpenGL/OpenGL ES с передачей результата как Image; это не Metal/D3D/AGSL и не zero-copy. Возможности и ограничения: [SHADERS.md](SHADERS.md).

## Расширение нативного API от 8 октября 2026

Ниже этого раздела сохранены исторические результаты предыдущей ревизии. Они не подтверждают новые изменения автоматически.

- Windows: 25 unit/integration-тестов и 1 doctest проходят. Проверены пропорциональные метрики, пустые строки, UTF-8/emoji/комбинируемые символы, переносы и пагинация; baseline- и layout-рисование дают одинаковые пиксели при scale 1, 1.5 и 2.
- Проверен настоящий цикл Win32 с автоматически закрывающимся окном: размер клиентской области, курсор, native_draw и пользовательское сообщение native_event.
- Общий host: проверены повторный вход, отсутствие повторного исполнения запросов, ошибки/отмена и отклонение некорректных входов до обращения к ОС.
- Clippy с -D warnings, форматирование, тесты ядра без default features и cargo doc проходят.
- Android: Java/JNI и APK собраны для ARM64 и x86-64. Отдельный пример native-api запущен в Android 16.1 x86-64 emulator; встроенные проверки нативных метрик и диапазонов Unicode проходят, реальный кадр просмотрен.
- Финальные артефакты: `native-api.exe` — **327 680 байт**, `gallery.exe` — **318 976 байт**, `rusterize-native-api.apk` с двумя ABI — **500 270 байт**. EXE проверен отдельным запуском из папки, содержащей только EXE; offscreen-кадр получен, код завершения 0. Импорты llvm-readobj содержат только системные DLL, VCRUNTIME/MSVCP отсутствуют.
- Генератор создал новый проект с актуальными hosts и NATIVE_API.md; cargo check этого проекта прошёл.
- Новые GTK/AppKit-адаптеры в этой сессии **не собраны и не запущены**: локального Linux/macOS окружения нет. Существующий CI нужно прогнать на этой ревизии перед выпуском. Изменения не отправлены в удалённый репозиторий.
- Диалоги выбора файлов и сообщения реализованы на desktop, но интерактивный выбор/отмена каждого диалога на всех ОС здесь не проверены. Системный буфер обмена Windows в тестах не перезаписывался.

Матрица функций, низкоуровневые расширения и оставшиеся пробелы: [NATIVE_API.md](NATIVE_API.md). Протокол стал RZ02; старые скопированные hosts нужно обновить.

Локальные результаты от 8 октября 2026 года. Это первая версия Canvas-фреймворка, а не зрелый универсальный набор виджетов.

| Windows offscreen | Проверены пиксели clipping, transform, restore, RGBA-порядок, DPI, текст, путь и градиент |
| Android ARM64 + x86-64 | Rust/JNI и Java собраны, APK подписан, apksigner verify проходит |

| Linux, macOS | Нативные сборки, Rust-тесты, Clippy, генератор и offscreen-кадры проходят в GitHub Actions; кадры просмотрены |

Последние добавления к оформлению окна проверяются компиляцией и фоновыми тестами, без повторного захвата пользовательского рабочего стола. Успешный DWM setter подтверждает принятие атрибута ОС; проверка пикселей заголовка отдельно не выполнена.

После добавления API оформления: Windows EXE **287 232 байт**, APK с двумя ABI **410 158 байт**. Точный размер зависит от версии Rust/SDK и внесённых изменений; размеры не являются обещанием для произвольного приложения.

Все пять заданий [CI для коммита b2c65ab](https://github.com/USBashka/Rusterize/actions/runs/37789557610) прошли: Windows, Linux, macOS, Android и ядро на Rust 1.85. Linux-бинарник занимает **1 098 896 байт**, macOS `.app` — **1 747 685 байт**. GTK/Pango/Cairo и системные фреймворки macOS в эти размеры не включены. В артефактах CI сохранены приложения и нативные кадры настольных ОС; APK имеет отладочную подпись, `.app` — ad hoc подпись без notarization.

С Linux/macOS проверены сборка и исполнение нативного рисования без окна. Интерактивная проверка клавиатуры, мыши и управления окном на этих двух ОС пока не выполнена. Минимальный deployment target macOS 11 задан и принят компилятором, запуск на самой macOS 11 отдельно не проверен.

Микробенчмарк: 1000 скруглённых прямоугольников, 2000 кадров, **66,9 мкс на запись + проверку + сериализацию кадра**, 36 016 байт на wire-кадр. Это не измерение нативного рендера, GPU, FPS или расхода батареи.

Windows использует статический CRT и системные графические DLL. Оконный пример запускался из каталога с готовым EXE. Импорты конечной сборки проверены через `llvm-readobj --coff-imports`: внешних DLL приложения и зависимостей от VCRUNTIME/MSVCP нет. Переносимость на чистую Windows 10 здесь ещё не проверена.

## Известные границы

- iOS, web, BSD и embedded не реализованы.
- Нет дерева виджетов, accessibility tree, IME/composition, экранной клавиатуры и готового редактора текста. Нативные text layout/metrics и clipboard добавлены в текущей ревизии.
- Есть один основной Canvas/окно; многоконность не реализована. Нативные диалоги добавлены в desktop-адаптеры текущей ревизии.
- Состояние приложения живёт в памяти; после уничтожения процесса/Activity требуется собственное сохранение.
- Большие изображения передаются в wire-кадре заново, хотя нативные Bitmap кэшируются. Для видео нужен отдельный ресурсный транспорт.
- Различия системных шрифтов, antialiasing и градиентов допустимы; идентичность каждого пикселя не обещается.
- GTK и macOS используют тонкие C/Swift-оболочки; прикладная логика остаётся Rust.

Текущий результат каждой публичной сборки: [GitHub Actions](https://github.com/USBashka/Rusterize/actions/workflows/ci.yml).
