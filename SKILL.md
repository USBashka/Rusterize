# Работа с Rusterize

Rusterize — фреймворк нативного Canvas. Логика приложения и рисование находятся в Rust; системные оболочки исполняют общий контракт. Основной пример — `examples/gallery`. Не предполагай, что пакет опубликован: используй локальную `path`-зависимость из checkout фреймворка.

## Начало работы

- Для нового приложения используй `cargo run -p rusterize-cli -- new <directory>` из checkout фреймворка. Генератор отказывается перезаписывать существующий каталог.
- Для существующего проекта сначала прочитай его `Cargo.toml`, реализацию `Application` и [API](docs/API.md). Не заменяй платформенную оболочку ради обычной правки интерфейса.
- Для сборки используй `python scripts/build.py --platform windows|android|linux|macos`; команды выполняются на соответствующей ОС, Android можно собирать с настольной системы.
- Прежде чем заявлять о поддержке конкретной ОС, прочитай [проверки и ограничения](docs/VALIDATION.md) и проверь доступный SDK. Код адаптера, успешная компиляция и запуск на устройстве — разные уровни доказательства.

## Инварианты приложения

- Реализуй `Application::event` и `Application::draw`. После изменения видимого состояния вызывай `Context::request_redraw`; непрерывные кадры включай только через `set_animation(true)` и отключай, когда они больше не нужны.
- Начальные размер, название и оформление окна задавай в `Application::window_options`, на Windows запускай через `run_app`. Для смены названия и цветов на ходу есть `Context::set_title` и `set_title_bar`. Не рисуй системный заголовок самостоятельно ради цвета; сверяй поддержку атрибутов с таблицей в API.
- Координаты событий и рисования уже в логических пикселях. Не умножай их повторно на `Viewport::scale`. Используй размер viewport для адаптивной компоновки; один расчёт границ должен обслуживать и рисование, и hit testing.
- `clear` разрешён только первым в кадре. Для локальных преобразований и clip предпочитай `with_save`. `Canvas::finish` вызывается движком; при ручном создании `Scene` вызови его сам и обработай ошибку.
- `text` принимает **базовую линию**, не верхний угол. Текст однострочный. Переносы, caret, выделение и полноценный редактор не реализованы этим методом.
- Сохраняй `Image` и сложные `Path` в состоянии приложения: их клоны дешёвые, повторное создание меняет ресурсный ID изображения. RGBA8 содержит обычный, не premultiplied alpha; конверсию делает бэкенд.
- Указатель захватывается логикой по ID. Активируй кнопку после `Up` внутри её границ, сбрасывай захват на `Cancel`, потере фокуса и `Suspend`. Для клавиатуры учитывай `repeat`.
- Все host handles принадлежат создавшему их UI-потоку. Не вызывай C/JNI-экспорты из фонового потока. `rusterize_data` действителен только до следующего изменяющего вызова для этого handle; его нельзя освобождать.
- `export_app!(App)` вызывается один раз в lib-crate и требует `Default`. Для Windows нужен bin с `rusterize::run_app`; Android требует `cdylib`, Linux/macOS — `staticlib`.

## Изменение бэкендов

Для добавления команды прочитай [архитектуру](docs/ARCHITECTURE.md) и [протокол](docs/protocol.md). Обнови Rust-проверку кадра, сериализатор и **все** декодеры. Изменение бинарной раскладки требует смены версии протокола. Не игнорируй неизвестную команду молча.

Сохраняй нативный путь рисования. Не добавляй WebView или поставляемый графический движок без запроса пользователя. Шрифты и сглаживание системные; не обещай идентичность пикселей между ОС. При расширении безопасного Rust API проверяй, что неверные значения не доходят до системного вызова.

## Проверка результата

Для изменения логики или бэкенда выполни `cargo fmt --all --check`, соответствующие тесты и Clippy. Проверь release-сборку. Для UI запусти именно нативный артефакт: протестируй действие, изменение размеров/DPI и idle/animation; картинка браузерного макета этого не заменяет.

В отчёте разделяй проверенное и непроверенное. Размер EXE/APK измеряй по конечному файлу. Заявление о самостоятельном Windows EXE подтверждай запуском из отдельной папки и проверкой импортов. Бенчмарк `scene` измеряет запись, валидацию и сериализацию команд, а не GPU, FPS или весь кадр.

Не публикуй пакеты, не отправляй изменения в Git и не устанавливай APK на произвольное физическое устройство без соответствующего запроса. Создание и проверка локального проекта не требуют отдельного согласования каждого шага.
